# PWA Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Tabellone (`apps/web`) installable as a PWA — placeholder
icons, a generated web manifest, a Turbopack-compatible service worker with
an app-shell-only offline cache, and the layout wiring to tie it together.

**Architecture:** Static placeholder icon PNGs generated once from committed
SVG sources; `app/manifest.ts` (Next's manifest file convention, not static
JSON) imports `strings.appName`; `serwist` + `@serwist/turbopack` serve the
compiled service worker through a Route Handler (this repo's Next 16.3.1
defaults to Turbopack, which the older webpack-based `@serwist/next` plugin
cannot target); the service worker precaches the static shell and an
`/~offline` fallback page, explicitly forces `/api/*` to `NetworkOnly` (no
cache fallback — a fetch failure must never resolve from a stale SW cache,
per this repo's stale-vs-failure invariant), and is excluded from the
`tsc` program because its `webworker` lib globals conflict with the rest
of the app's `dom` lib.

**Tech Stack:** `serwist` 9.x, `@serwist/turbopack` 9.x, `esbuild` (native,
required peer), `sharp-cli` (one-off icon rasterization via `npx`, not an
added dependency), Next 16.3.1 App Router / Turbopack.

**Spec:** `docs/superpowers/specs/2026-08-18-pwa-setup-design.md`

```bash
npx -y sharp-cli -i apps/web/public/icons/src/icon.svg -o apps/web/public/icons -f png resize 192 192
mv apps/web/public/icons/icon.png apps/web/public/icons/icon-192.png

npx -y sharp-cli -i apps/web/public/icons/src/icon.svg -o apps/web/public/icons -f png resize 512 512
```

`sharp-cli` writes `<output-dir>/<input-basename>.png` (extension changed

### Task 4: Service worker source

**Files:**
- Create: `apps/web/src/app/sw.ts`

- [ ] **Step 1: Write the service worker**

```ts
/// <reference lib="esnext" />
/// <reference lib="webworker" />
import { defaultCache } from '@serwist/turbopack/worker'
import type { PrecacheEntry, RuntimeCaching, SerwistGlobalConfig } from 'serwist'
import { NetworkOnly, Serwist } from 'serwist'

declare global {
  interface WorkerGlobalScope extends SerwistGlobalConfig {
    __SW_MANIFEST: (PrecacheEntry | string)[] | undefined
  }
}

declare const self: ServiceWorkerGlobalScope

const apiNetworkOnly: RuntimeCaching = {
  matcher: ({ sameOrigin, url }) => sameOrigin && url.pathname.startsWith('/api/'),
  handler: new NetworkOnly(),
}

const serwist = new Serwist({
  precacheEntries: self.__SW_MANIFEST,
  skipWaiting: true,
  clientsClaim: true,
  navigationPreload: true,
  runtimeCaching: [apiNetworkOnly, ...defaultCache],
  fallbacks: {
    entries: [
      {
        url: '/~offline',
        matcher({ request }) {
          return request.destination === 'document'
        },
      },
    ],
  },
})

serwist.addEventListeners()
```

`apiNetworkOnly` is listed before `...defaultCache` because Serwist/Workbox
routing matches rules in array order — this shadows `defaultCache`'s own
`/api/*` rule, which is `NetworkFirst` with a 24h cache fallback (exactly
the stale-while-offline behaviour the invariant forbids for board reads).

### Task 5: Serwist route handler

**Files:**
- Create: `apps/web/src/app/serwist/[path]/route.ts`

- [ ] **Step 1: Write the route handler**

```ts
import { spawnSync } from 'node:child_process'
import { createSerwistRoute } from '@serwist/turbopack'

const revision =
  spawnSync('git', ['rev-parse', 'HEAD'], { encoding: 'utf-8' }).stdout?.trim() ||
  crypto.randomUUID()

export const { dynamic, dynamicParams, revalidate, generateStaticParams, GET } = createSerwistRoute({
  swSrc: 'src/app/sw.ts',
  useNativeEsbuild: true,
  additionalPrecacheEntries: [{ url: '/~offline', revision }],
})
```

`revision` cache-busts the `/~offline` precache entry per commit so a
stale offline page never survives a deploy. `useNativeEsbuild: true` uses
the `esbuild` dependency from Task 3 instead of the slower `esbuild-wasm`
fallback (this only runs in Node, never shipped to the browser).
